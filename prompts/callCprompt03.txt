Important corrections
The Voice Agent / Call Centre backend is multi-domain, not banking-only.

Banking names and examples in the API documents are examples from the current deployment and must not be treated as an architectural limitation.

The frontend architecture and service layer must remain domain-neutral.

Do not fabricate data for unsupported domains.

The existing APIs are a starting point, not an immutable contract.

Where the UI requires real functionality not currently exposed by the backend, classify the requirement and recommend whether to:

extend an existing API,
add a new API,
derive the value from existing data,
add backend persistence/workflow logic,
modify the UI,
or remove the UI element if it has no meaningful product purpose.

Decisions must be case by case.

The final system must contain no mock, random, simulated or demo data.

However, do not delete mock data yet. Use it as a source for understanding intended functionality until the live replacement design is approved.

Existing WhatsApp/Supabase/Twilio functionality remains in scope as an existing live module. Do not redesign it yet.
Vapi is legacy and will eventually be removed completely.
Authentication and User Management backend implementation remain last priority, but their functional requirements should still be analysed now.
